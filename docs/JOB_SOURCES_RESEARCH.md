# Источники вакансий: API → MCP → ATS

Проверено 2–3 октября 2026 года по первичной документации. Приоритет — Европа, но рынок, локация и фильтры задаются запросом и профилем. Это исследование подключения источников, не подборка подтверждённых вакансий для конкретного человека.

## Решение для первого этапа

Бесплатное ядро — **Greenhouse, Lever, Ashby, SmartRecruiters** для выбранных компаний; **Arbeitnow и Remotive** для обнаружения вакансий. **Adzuna** — следующий broad-discovery после получения ключей. **Google Jobs через SerpAPI** — дополнительный мета-поиск в пределах бесплатной квоты; **Jooble** — резервный канал с отдельным ключом для рынка.

ATS-провайдеры публикуют доски отдельных работодателей, а не общий каталог всех компаний. Поэтому цикл состоит из поиска роли/компании через агрегаторы и web-search, добавления её доски, проверки новых вакансий и ведения личной воронки. Одна вакансия может обнаружиться несколькими путями; источники наблюдения сохраняются отдельно от этапа отклика.

Автоматического повышения лимита и покупки подписки нет.

## Web-search как отдельный канал

Вкладка содержит LinkedIn, Indeed, Welcome to the Jungle, Wellfound, EURES и поиск карьерных страниц ATS. Это генераторы поисковых запросов из текущих ключей, исключений и географии профиля. Кнопка открывает поиск в браузере; MCP `jobs_web_search_plan` отдаёт те же запросы для web-tools чата.

Результат поисковика нужно проверить на странице вакансии: прямой URL, работодатель, открытый приём откликов, дата и ограничения удалённой работы. После проверки `jobs_ats_import` сначала даёт preview, затем сохраняет карточки с `store=true`. Если найдена поддерживаемая доска компании — `jobs_add_company_board` подключает её для следующих проверок. LinkedIn не представлен как свободный API и не обходится автоматически. EURES пока web-канал; открытый глобальный API-доступ для этого проекта не подтверждён.

## Мониторинг компаний

1. Добавить существующую или новую компанию, ATS-платформу, URL/slug доски, профиль фильтрации и интервал. Короткий идентификатор не является секретным токеном.
2. `jobs_monitor_companies` без `execute` показывает, какие включённые доски пора проверить. При `execute=true` обрабатывает их последовательно с общим `maxRequests`.
3. По умолчанию интервал — 12 часов; доступны 6–168 часов. Пока запуск только по кнопке/MCP/CLI. Интервал означает срок следующей допустимой проверки, а не наличие фонового планировщика.
4. Сначала получить полный снимок доски. Оборванная пагинация, неправильный формат, ошибка HTTP и исчерпание бюджета не меняют отметки отсутствия. Вся загрузка одной доски применяется транзакционно.
5. По фильтрам добавить/обновить подходящие карточки. Для уже известных публикаций проверять наличие по полному снимку, включая не прошедшие текущие фильтры.
6. После двух свежих успешных снимков без публикации показать «не найдена». Это наблюдение об источнике, не гарантированное закрытие роли. Не удалять карточку и не менять этап отклика. Повторное появление сбрасывает отметку.

Следующий этап: фоновый worker раз в час выбирает due-доски, распределяет запросы и повторяет ошибки с backoff; уведомляет только о новых подходящих позициях и изменениях. Для 30 небольших досок два прохода в сутки — ориентировочно 60 списочных запросов/сутки; Lever/SmartRecruiters потребуют больше при пагинации, детали SmartRecruiters — ещё один запрос на выбранную карточку. Это оценка нагрузки, не заявленная квота ATS.

## Хранение и границы реализации

Существующая SQLite ATS переиспользуется: `jobs`, `companies`, `profiles`, `sources`. Добавлены `provider_requests` (локальный расход), `provider_cache`, `source_runs` (до 500 запусков, последние 100 в UI) и `job_observations` (происхождение, первое/последнее наблюдение, число отсутствий). Статус адаптера и включение сохраняются в `settings`. Новые поля доски: `companyId`, `profileId`, `monitoring`, `intervalHours`, `location`.

Один HTTP-сервер обслуживает UI, CLI и stdio MCP: общие лимиты, кэш и база. Кэш не расходует запросы и сохраняет исходную дату наблюдения. Лимит запуска действует на реальные HTTP-запросы, а не число вакансий. Локальные месячные счётчики используют UTC, считают даже неуспешные попытки консервативно и не учитывают вызовы тем же ключом вне приложения; внешняя квота может оказаться меньше.

Дубликаты объединяются по каноническому URL или ID внутри устойчивого источника. Для ad-hoc discovery источник стабилен (`discovery:adzuna` и т.п.), поэтому другая формулировка поиска не создаёт копию по тому же внешнему ID. Разные URL одной и той же роли на разных агрегаторах пока не объединяются семантически. Для совпавшего URL сохраняются отдельные наблюдения провайдеров. Обновление источника сохраняет этапы, историю, заметки, избранное и follow-up. Описания из другого источника не перетирают автоматически первичную карточку.

Фильтры поиска: keyword-группы соединяются OR; `|` задаёт синонимы, исключения убирают совпадения. Формат, уровень и минимальная зарплата проверяются строго. География — совпадение текста локации с одним из значений профиля; «Европа» пока не разворачивается в страны. Для реальных регионов лучше перечислить названия стран/городов или передать явные `locations`. `country` выбирает рынок агрегатора; отдельное поле `location` — поисковую локацию. Работа remote не означает доступность из любой страны.

Даты не угадываются: Greenhouse `updated_at`, Jooble `updated` и относительные SerpAPI `posted_at` не становятся датой публикации. Ashby возвращает дату последней публикации. `maxAgeDays` фильтрует подтверждённые даты; `includeUnknownDate=false` исключает записи без даты. SmartRecruiters списочный ответ может не содержать описание: `jobs_enrich` получает его для выбранной ATS-карточки за один запрос. Автоматический enrichment всех ролей пока не включён.

JSON-экспорт сохраняет вакансии, компании, профили и настройки досок, но не кэш, квоты, историю вызовов и наблюдения. Для полного резервного копирования нужна штатная копия SQLite. Отправка резюме/откликов отсутствует.

## Токены и следующие действия

Для Greenhouse / Lever / Ashby / SmartRecruiters / Arbeitnow / Remotive токены не нужны. Достаточно добавлять интересующие компании и их карьерные доски.

В игнорируемый `.env` проекта можно позже добавить:

- Adzuna: `ADZUNA_APP_ID`, `ADZUNA_APP_KEY`.
- SerpAPI: `SERPAPI_API_KEY`.
- Jooble: `JOOBLE_API_KEY`, дополнительно несекретные `JOOBLE_COUNTRY` и `JOOBLE_HOST` из условий регионального доступа.

После изменения `.env` нужно перезапустить локальный сервер. Ключи не передаются в UI, инструменты MCP, экспорт или сообщения. Текущее подключение MCP описано в [MCP.md](MCP.md).

## Проверки

3 октября 2026 на изолированной базе без ключей публичные API успешно вернули: Greenhouse (`greenhouse`) — 18, Lever (`lever`) — 0, Ashby (`Ashby`) — 61, SmartRecruiters (`smartrecruiters`) — 1, Arbeitnow — 326, Remotive — 17 нормализованных записей. По одному HTTP-запросу на провайдера. Эти числа — снимок ответа, не обещание охвата и не персональная подборка; в рабочую ATS они не импортировались.

Adzuna, SerpAPI и Jooble проверены на контрактах/фикстурах, реальная авторизация ещё требует пользовательских ключей. Автоматические тесты используют только временные SQLite-базы. MCP проверяется реальным stdio-клиентом через временный HTTP-сервер, включая dry-run, импорт и сохранение этапов.
