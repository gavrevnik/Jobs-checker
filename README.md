# Jobs checker

Локальное приложение для одного пользователя: поиск компаний и вакансий, личная воронка и объяснимое сопоставление с профилем поиска. React + TypeScript, Express, SQLite. Облачная база и аккаунт не нужны.

## Общие библиотеки и владение данными

Повторно используемые provider-клиенты находятся в соседнем `personal-radar/connectors/`; нужен checkout Personal Radar в стандартном Life Stack layout. [Установка и структура пакетов](../personal-radar/connectors/README.md), [inventory переносов](../personal-radar/docs/connector-inventory.md), [Knowledge/SQLite и future migration](../personal-radar/docs/storage-boundaries.md).

npm использует `file:../personal-radar/connectors/connectors-ts` и именованные импорты `@personal-radar/connectors/...`. Обычные install/dev/start/build/check/test и MCP-команды автоматически собирают библиотеку; при первом setup устанавливаются её lockfile-зависимости. Ручные symlink не нужны.

SQLite-файлы, текущие карточки/профили/оценки и API/MCP/UI контракты сохранены. Долгосрочные отобранные sources/owners/items/preferences принадлежат Personal Radar Knowledge; существующие локальные данные пока не мигрируют. Discovery сохраняет source-кандидатов с identity/provenance/relevance и явным review; подтверждённые источники предназначены для будущего отдельного переноса в Knowledge. Ручной versioned catalog sync и outbox для явно определённых канонических полей описаны в [Catalog Sync](../personal-radar/docs/catalog-sync.md); новые кандидаты требуют утверждённого manifest.

## Источники → MCP → ATS

Новая отдельная вкладка **Источники** находится под **Полезными ресурсами**. В ней — каталог из девяти API-адаптеров со статусами и выключателями, поиск по ключам и активному профилю, доски компаний, web-search и история запросов. Существующий справочник ресурсов сохранён.

Без ключей доступны Greenhouse, Lever (Global/EU), Ashby, SmartRecruiters, Arbeitnow и Remotive. Adzuna, Google Jobs через SerpAPI и Jooble используют серверные ключи из `.env` по образцу `.env.example`. Adzuna подключена и проверена; SerpAPI и Jooble ожидают ключи. География задаётся профилем и запросом. Кнопка поиска сохраняет подходящие вакансии в существующую ATS, если включено «Сохранять в ATS»; этапы, заметки и избранное сохраняются.

Мониторинг досок запускается кнопкой или MCP после настроенного интервала (по умолчанию 12 часов). Фоновое расписание пока не включено. Два отсутствия в полных свежих снимках отмечаются отдельно; карточки автоматически не удаляются. SmartRecruiters возвращает краткий список, описание выбранной карточки загружается `jobs_enrich`.

Доступны `npm run tools` и `npm run mcp` через локальный HTTP-сервер. Начните с `jobs_sources_status`, затем `jobs_profiles` и `jobs_search`; без `execute=true` поиск возвращает план без внешних вызовов. Кэш и квоты общие с UI. Новый слой добавляет таблицы SQLite без сброса старых записей.

На карточках Adzuna, SerpAPI и Jooble показан расход запросов из SQLite. Наведение на счётчик раскрывает остаток, тариф, временные окна и ближайшее обновление. При расходе от 80% он желтеет, при исчерпании любого лимита краснеет; новые сетевые вызовы блокируются до освобождения квоты. Локальный кэш доступен и после достижения лимита. Открытая вкладка обновляет показатели каждые 30 секунд и при возвращении в окно, без запросов к провайдерам.

- **Adzuna:** 2 500 за локальный календарный месяц (1-е число, 00:00 UTC), 1 000 за последние 7 дней, 250 за 24 часа и 25 за минуту. Границы месячного периода и часовой пояс сброса Adzuna не подтверждены публичной документацией (проверено 03.10.2026); это локальный защитный расчёт, не баланс кабинета.
- **SerpAPI:** Free — 250 за расчётный цикл, 50 за час. В `.env` можно задать `SERPAPI_BILLING_ANCHOR` — ISO timestamp начала/продления цикла из кабинета, например `2026-10-15T09:00:00Z`. Сброс происходит ежемесячно в эту дату/время UTC; для короткого месяца берётся последний день без смещения следующих месяцев. Без даты используется консервативное скользящее окно 31 день. При смене тарифа задайте `SERPAPI_MONTHLY_LIMIT` и `SERPAPI_HOURLY_LIMIT` по подписке и обновите дату, если она изменилась. Перезапустите сервер после изменения `.env`.
- **Jooble:** Free — 500 запросов на региональный ключ за всё время, без периодического сброса. Ключ различается по хэшу; сам секрет в журнал не попадает. Старые записи без привязки к ключу включены консервативно.

У SerpAPI из расхода за цикл исключаются известные HTTP/API-ошибки и ответы с уже учтённым search ID. Успешный пустой результат считается запросом. Старые записи без исхода, незавершённые и сетевые ошибки с неизвестным результатом остаются в оценке расхода; часовой лимит учитывает все попытки. У Adzuna и Jooble считаются все отправленные попытки. История сохраняется при смене периода и перезапуске. Это общий локальный учёт UI/API/MCP, а не баланс кабинета провайдера: обращения из других приложений не видны. Условия: [Adzuna](https://developer.adzuna.com/docs/terms_of_service), [SerpAPI](https://serpapi.com/pricing), [Jooble](https://help.jooble.org/en/support/solutions/articles/60001448238-rest-api-documentation).

## Запуск

На macOS дважды нажмите **[Jobs checker.app](Jobs%20checker.app)** в папке проекта. Ярлык запустит сервер в фоне и откроет интерфейс в браузере по умолчанию, без окна Terminal и дополнительных ручных команд. Если Jobs checker уже работает из этой папки, повторный клик просто откроет его.

При первом запуске при необходимости устанавливаются зависимости; при каждом запуске остановленного сервера собирается актуальный интерфейс. Используется существующая база. Логи и PID процесса сохраняются в `.runtime/web.log` и `.runtime/web.pid`. Приложение продолжает работать после закрытия вкладки. Сам `Jobs checker.app` должен оставаться в папке проекта; для рабочего стола или Dock можно создать псевдоним через Finder. `PORT` из `.env` учитывается; занятый чужим процессом порт показывает сообщение об ошибке.

При запуске через Life Hub вкладка отправляет локальный heartbeat. После закрытия всех вкладок Life Hub может остановить сервис по PID согласно политике `stopWhenBrowserIdle`.

Нужен **Node.js 22.13+** (рекомендуется актуальная LTS-версия).

```sh
npm ci
npm run dev
```

Открыть **http://jobs-checker.localhost** через установленный в `life-hub` Caddy. Внутренний адрес — `http://127.0.0.1:4317`. Один процесс обслуживает API и интерфейс.

Для обычного использования без режима разработки:

```sh
npm run build
npm start
```

В стандартной структуре `life-stack` база создаётся в `../data/jobs-checker/scout.sqlite`. При ручном запуске остановка — `Ctrl+C`. Повторный запуск сохраняет данные. Сервер слушает только `127.0.0.1`; доступ из локальной сети выключен. Путь базы, `SCOUT_DB` и ключ сохранённого профиля сохранены для совместимости после переименования Scout в Jobs checker. Можно изменить `PORT` и `SCOUT_DB` в `.env` по образцу `.env.example`.

## Первый запуск

1. В **Профилях поиска** настройте ключевые слова, исключения, географию, формат работы, уровень и зарплату. Можно создать несколько профилей.
2. В **Полезные ресурсы → Ресурсы** нажмите «Обновить» у Remotive либо добавьте карьерную страницу компании на Greenhouse, Lever или Ashby.
3. В **Вакансиях** используйте поиск, фильтры и сортировку по совпадению. Сохраните интересное в избранное или переведите на этап «В планах».
4. В карточке добавляйте заметки и дату следующего действия. Действия на сегодня доступны по значку колокольчика. Воронка поддерживает перетаскивание и выбор этапа в карточке.
5. В **Компаниях** можно вести список работодателей без открытых вакансий. В ленте — кликабельное название, дата проверки и источник, сфера, офис, формат работы, краткое описание, размер и data-driven оценка; зарплата появляется при наличии данных. Заметки и обоснование оценки открываются через «Карточка и заметки».
6. Фильтры компаний: название/описание/сфера/локация, тип, страна, формат, размер, минимальная data-driven оценка, источник, статус, дата проверки; дополнительно — наличие вакансий, грейд и нижняя граница зарплаты в выбранной валюте и периоде. «Показать вакансии выборки» открывает только вакансии, соответствующие условиям. Страна, формат, грейд и зарплата должны совпадать в одной вакансии; неизвестная зарплата не считается нулевой.

Европейское расширение от 21.09.2026: [8 вакансий, 5 новых компаний и справочные данные для 39 карточек](research/europe-product-analytics-2026-09-21.md). Профиль «Европа · Product analytics · Middle+» добавлен отдельно от испанского. База пользователя после этой итерации содержит 43 вакансии; их наличие в базе не означает автоматическую актуальность всех старых публикаций.

Новая база пустая. Кнопка «Сначала посмотреть на примерах» добавляет вымышленные компании и вакансии с пометкой **Демо**. Их можно убрать общей кнопкой. Демонстрационные записи не являются реальными предложениями работы.

## Как пополняется база

Вакансии поддерживают отдельную AI-оценку 0–10: краткий вывод в списке, обоснование, профиль, дата и источники в карточке. Сортировка «высокий AI-score» поднимает оценённые роли. Оценку выставляет агент после чтения профиля и вакансии через `jobs_ats_update`; это содержательное суждение на указанную дату. Процент «Фильтр» остаётся отдельным совпадением по правилам. Обновление источника сохраняет AI-оценку; после изменения требований её нужно пересмотреть.

| Способ                   | Что даёт                                                       | Что требуется                 |
| ------------------------ | -------------------------------------------------------------- | ----------------------------- |
| Remotive                 | Открытая лента удалённых вакансий разных компаний              | Ничего; источник уже добавлен |
| Greenhouse               | Публичные вакансии конкретной компании                         | Ссылка или board token        |
| Lever                    | Публичные вакансии конкретной компании, включая EU             | Ссылка или site name          |
| Ashby                    | Публичные, перечисленные на доске вакансии компании            | Ссылка или job board name     |
| Adzuna                   | Поиск по запросу и стране, до 150 свежих результатов за запуск | APP ID и API Key              |
| Ручной ввод / JSON / CSV | Любые найденные компании и вакансии, в том числе из чата       | Название компании и должность |

Вкладка «Полезные ресурсы → Ресурсы» принимает ссылки вида `https://jobs.ashbyhq.com/company`, `https://jobs.lever.co/company`, `https://jobs.eu.lever.co/company`, `https://job-boards.greenhouse.io/company`. Можно указать только короткий идентификатор `company`. В поле названия нужно указать компанию: это название попадёт в вакансии.

Это публичные API публикаций работодателей, а не глобальный поиск по всем компаниям этих ATS. Новые компании находятся через общую ленту Remotive, Adzuna или внешнее исследование; затем их можно отслеживать отдельно. Произвольные сайты, LinkedIn и страницы за авторизацией автоматически не обходятся.

В старом разделе «Ресурсы» обновление запускается вручную. Remotive ограничен одним успешным запросом в 6 часов, остальные источники — в 15 минут. После ошибки повторный запрос возможен через минуту. Ограничения сохраняются в SQLite и переживают перезапуск. Новый поиск дополнительно использует общий кэш ответов и лимит `maxRequests`, Adzuna — локальные 25/мин, 250/день, 1 000/неделю, 2 500/месяц; SerpAPI по умолчанию — 50/час и 250/цикл, Jooble — 500 на ключ за всё время. Правила окон и учёта ошибок описаны выше; обращения из других приложений не видны. Включённые источники загружаются последовательно, чтобы не создавать всплеск запросов. Ошибка одного источника не отменяет успешные загрузки остальных.

Дубликаты определяются по URL без tracking-параметров, по ID публикации внутри источника и, если ссылки нет, по названию, компании и географии. Параметры URL, идентифицирующие вакансию, сохраняются. Семантические дубликаты одной роли на разных сайтах с разными ссылками автоматически не объединяются.

Обновление источника сохраняет **этап, историю этапов, избранное, заметки и дату следующего действия**. Описание и другие сведения источника могут обновляться. Удалённая вручную вакансия может появиться при следующей загрузке; чтобы скрыть её надолго, используйте архив. Исчезновение из ленты не означает автоматического удаления: перед откликом проверяйте ссылку. В карточке показана дата последней успешной проверки записи.

## Adzuna — необязательное подключение

MCP `jobs_search` и HTTP API поддерживают нативный блок `adzuna`: зарплата, неизвестная зарплата, свежесть, слова/фразы/заголовок, компания, категория, география/радиус, занятость, договор, сортировка и пагинация. [Все фильтры и пример](docs/ADZUNA_FILTERS.md). Эти параметры применяет провайдер; локальные фильтры профиля работают дополнительно. Форма UI пока передаёт базовые параметры; расширенные доступны через MCP/API.

1. Зарегистрироваться на [developer.adzuna.com](https://developer.adzuna.com/).
2. Скопировать `.env.example` в `.env` и добавить:

```dotenv
ADZUNA_APP_ID=your_app_id
ADZUNA_APP_KEY=your_api_key
```

3. Перезапустить сервер и добавить источник Adzuna с запросом и страной.

Ключи используются только сервером, не возвращаются в интерфейс и экспорт. Коннектор проверен на образцах ответов и живым MCP-запросом 03.10.2026: поиск `product analyst`, рынок `es`, одна страница вернула 50 вакансий. Ключи хранятся локально в `.env` (права `600`), файл исключён из Git. Для нового развёртывания нужны собственные ключи. Условия доступа, квоты и доступные рынки определяются провайдером. Прогнозируемая Adzuna зарплата подписана как оценка и не используется как подтверждённая зарплата в фильтре.

## Импорт из чата

Нажмите **Импорт → Промпт для чата**, вставьте промпт в чат, добавьте свои критерии и попросите исследовать реальные компании/вакансии. Полученный JSON вставьте в окно импорта или выберите файл. Сначала появится предпросмотр. Файл целиком валидируется до записи; ошибка не оставляет половину импортированной подборки.

Пример: [examples/import.json](examples/import.json). Для вакансии обязательны только `title` и `company`; для компании — `name`. Неизвестные поля лучше пропустить. Не подставляйте выдуманные зарплаты или географию. Поддерживаются компании без вакансий, массив вакансий без обёртки, JSON в блоке Markdown и CSV.

CSV-пример: [examples/jobs.csv](examples/jobs.csv). Заголовки соответствуют полям вакансии; теги внутри ячейки разделяются `;`. CSV предназначен для вакансий, компании импортируются JSON.

Также доступен локальный API для заполнения базы из скрипта или в следующей сессии работы с этим проектом:

```sh
curl -X POST http://127.0.0.1:4317/api/import/preview \
  -H 'Content-Type: application/json' \
  --data-binary @examples/import.json

# После проверки содержимого:
curl -X POST http://127.0.0.1:4317/api/import \
  -H 'Content-Type: application/json' \
  --data-binary @examples/import.json
```

Подробности — в [docs/API.md](docs/API.md).

## Профиль и совпадение

Профиль поддерживает диапазон **Middle / Senior / Lead**, синонимы внутри одного критерия (`product analyst | product analytics`) и текстовый контекст поиска. Синонимы соединяются через `|` и дают баллы один раз, если найден хотя бы один вариант. Разные критерии по-прежнему разделяются запятыми. Контекст сохраняет приоритеты компаний и задач, но не участвует в расчёте процента. Неизвестный уровень не считается совпадением с диапазоном.

Оценка детерминированная и не требует LLM API. Вес слов — 50, формата — 20, географии — 15, уровня — 10, зарплаты — 15. Учитываются только настроенные критерии, результат нормируется к 100%. Все слова профиля имеют равный вес внутри блока; отсутствие части слов снижает оценку. Проверяются подстроки в названии, описании, компании, географии и тегах.

География совпадает, если в указанной локации есть хотя бы один регион из профиля. `Remote` не означает право работать из любой страны. Валюта и период зарплаты должны совпадать буквально; сравнивается известная нижняя граница, без конвертации валют и пересчёта часов. Неизвестное поле не считается совпадением. Исключённое слово даёт ноль и скрывает запись из списка; это можно отменить в дополнительных фильтрах. Без критериев процент не отображается.

## Карточки компаний и активный профиль

Активный поисковый профиль отображается и переключается компактной плашкой в левой панели. В узком окне видна аббревиатура, а полное имя — во всплывающей подсказке и списке выбора.

Под названием компании находится ссылка на её сайт. Иконки загружаются напрямую с сайтов компаний без передачи адреса страницы Jobs checker; если сайт не отдаёт иконку или интернет недоступен, остаются инициалы. Ссылка использует поле «Сайт» из карточки компании.

## Полезные ресурсы

В боковом меню под профилями доступен раздел «Полезные ресурсы» с тремя вкладками:

- **Ресурсы** — подключённые источники загрузки, настройки и результаты обновления.

- **Ресурсы для поиска** — исходная подборка из 13 площадок для поиска вакансий, изучения команд, зарплат и переезда.
- **Ресурсы для изучения компаний** — 12 ресурсов: отзывы сотрудников и клиентов, профили коллег, зарплатные данные, базы бизнеса, технические блоги и отчёты. Каждая карточка подсказывает, что выяснить о конкретном работодателе перед интервью.

В обеих вкладках есть поиск, фильтры назначения, сортировка, ссылки на первичные источники и авторская оценка пользы под Product Analyst middle+/senior в Европе. При переключении вкладки поисковая строка и фильтр сбрасываются; вкладки доступны с клавиатуры стрелками, Home и End. Оценки учитывают задачу вкладки, фиксированы на дату проверки (21.09.2026) и не пересчитываются при смене профиля. Один ресурс может использоваться для обеих задач. Справочник не означает наличие интеграции: Greenhouse-доски подключаются отдельно во вкладке «Ресурсы», вакансии можно заносить вручную или импортом, а выводы об работодателе — в заметки компании.

## Экспорт и резервная копия

**Экспорт JSON** выгружает компании, вакансии с историей, профили и настройки источников. JSON можно импортировать на другом компьютере. При импорте существующие записи пропускаются: это объединение, а не полная замена базы. Даты и история новых вакансий сохраняются, связи с импортированными источниками восстанавливаются; время синхронизации нового источника сбрасывается. ID сущностей могут измениться.

Для точной резервной копии **остановите приложение** и скопируйте `../data/jobs-checker/` целиком. Для восстановления, при остановленном приложении, замените каталог резервной копией. Не копируйте только `.sqlite` во время записи: SQLite использует WAL-файлы. Данные и `.env` исключены из Git через `.gitignore`.

Интерфейс, заметки и воронка работают без интернета после установки зависимостей и сборки. Шрифты включены в сборку. Интернет нужен для обновления источников и перехода на внешние вакансии. Приложение не отправляет ваши заметки или профиль LLM-провайдерам. Adzuna получает только настроенный поисковый запрос и страну.

## Проверки и структура


Живая проверка — сетевой тест, не часть `npm test`; запускайте её редко из-за ограничений Remotive. Пустая доска вакансий — допустимый ответ.

## Аналитика

Раздел «Аналитика» с глобусом в боковом меню показывает вакансии из базы. Общие фильтры: страны (можно несколько), запрос, формат, уровень, этап, совпадение с активным профилем и зарплата. По умолчанию архив исключён.

Карта работает локально на данных Natural Earth: масштаб, перетаскивание, виды «Европа»/«Мир», кнопка показа всех локаций. Клик по стране включает фильтр, по точке — список вакансий с переходом в карточку. Городские точки и условные точки страны различаются. Общие регионы и неизвестные места не геокодируются произвольно; такие вакансии доступны в списке и через фильтр неопределённой географии. Несколько локаций одной вакансии не увеличивают общие итоги.

Зарплаты показываются отдельными группами валюты/периода: медианы нижних границ, центров и верхних границ, гистограмма выбранного показателя и интервалы по вакансиям. Центр вычисляется только при обеих границах. Нет автоматического пересчёта валют и периодов; значения из свободного текста и неизвестные суммы не принимаются за ноль. Числовой фильтр применяется к выбранной границе/центру и исключает несопоставимые суммы; без него карта включает вакансии без зарплаты.

## Память поиска

После исследовательской сессии стратегия, точные параметры запросов, результаты, рекомендации и ID добавленных вакансий сохраняются в SQLite `discovery_reviews`. MCP `jobs_discovery_history` читает историю перед следующим поиском; `jobs_discovery_save` создаёт или обновляет summary по стабильному ID. История не обрезается вместе с техническими логами. Она входит в резервную копию SQLite; обычный JSON-экспорт ATS пока её не включает.

[Архитектура, ownership и команды](../personal-radar/docs/catalog-sync.md). Каталог отображает время последнего sync; глобальный интерес к связанным источникам редактируется отдельно от локального мониторинга. ## Проверка архитектурной интеграции

Полный CI с приватным общим пакетом выполняется в Personal Radar (`Validate connectors and consumers`): clean install, imports, unit/MCP tests и production builds во временной структуре Life Stack. После изменения приложения запустите этот workflow в Personal Radar; source checks этого публичного репозитория проверяют доступную без приватных credentials часть и не заменяют integration CI. В workflows нет provider calls, пользовательских БД и опубликованных токенов.
