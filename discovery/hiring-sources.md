# Careers, ATS и LinkedIn · discovery и мониторинг

## Обязательная проверка источников

До поиска вакансий через агрегаторы для каждой существующей companyId найди официальный Careers и определи доступный ATS. Сначала прочитай сохранённый `company.hiringSources` и доски `sources`; повторный поиск identity нужен при отсутствии, конфликте, явной смене адреса или запросе обновления. С официального сайта проверь Careers/Jobs/Work with us и прямую ссылку на внешнюю ATS. При отсутствии ссылки используй адресный web search по имени и домену. Зафиксируй недоступность/не найденное, затем продолжай доступными источниками. Не обходи блокировки, не перебирай угаданные ATS slug. Публичный ATS с одноимённым работодателем без достаточного сопоставления — кандидат, а не подтверждённая связь.

Приоритет сбора: подтверждённый официальный Careers/ATS → агрегаторы/API в разрешённом бюджете → адресный веб-поиск, включая LinkedIn → содержательная сводка. Официальный сайт может размещать роли на внешней ATS. Не подменяй найм компании общей отраслевой доской, вакансиями её клиентов, дочерним/региональным подразделением или одноимённой организацией.

## Веб-поиск по запросу исследования или мониторинга

Это обязательная оценка каналов по релевантности и пробелам, а не требование обходить все сайты для каждой компании. В discovery ищи кандидатов по ролям/рынку, затем исследуй конкретного работодателя. В monitoring добавляй подтверждённое имя/алиасы компании и используй сохранённые ссылки. Роли, грейды, страны и исключения бери из актуального профиля. Официальный Careers проверяй первым; дополнительные площадки — после него и доступных API.

| Канал | Как применять |
| --- | --- |
| **Careers / Workday** | Если официальный Careers ведёт на Workday, читай именно эту доску. Для пробела — адресный поиск `"Company" site:myworkdayjobs.com ("Product Analyst" OR "Data Analyst")`, затем проверь связь с официальным сайтом; собственный домен работодателя также возможен. Workday — платформа карьерных сайтов компаний; отдельного локального API-адаптера нет. Не перечислять угаданные tenant URL и не использовать закрытый customer API. |
| **Indeed** | Дополнительный охват локального рынка: имя компании + целевые роли, `site:indeed.com` или соответствующий региональный домен. Извлеки реального работодателя, отличи агентство/клиента и устаревший репост; по возможности перейди к официальному объявлению. |
| **Welcome to the Jungle (WTTJ)** | `site:welcometothejungle.com` + компания/роль/страна. Проверяй вакансии и публичный профиль команды; рекламное описание культуры не становится verified evidence без конкретного материала. |
| **Wellfound** | `site:wellfound.com` + компания/аналитические роли. Полезно для стартапов и продуктовых команд; отдельно проверяй допустимые страны remote, тип занятости и base/equity. |
| **EURES** | `site:eures.europa.eu` + роль/страна/компания; переходи к исходной национальной службе или работодателю. Наличие вакансии в ЕС не доказывает право кандидата вне ЕС на работу или visa sponsorship. |
| **LinkedIn** | Сохранённый профиль компании → Jobs и адресный поиск публичных `/jobs/view/`; identity и границы ниже. |

`jobs_web_search_plan` возвращает только запросы/ссылки. Агент должен действительно выполнить релевантный поиск доступным web tool, прочитать доступные объявления и сохранить outcome/provenance; если инструмент недоступен или канал пропущен, явно зафиксировать пробел/причину. Search engine dates/snippets не доказывают публикацию и активность. Не использовать login-wall обход, cookies, CAPTCHA/proxy bypass; недоступность канала не означает ноль вакансий. Отдельные Indeed/WTTJ/Wellfound/EURES/Workday executors не подключены.

## Jobicy · бесплатная общая лента

Публичный REST без ключа/Authorization и кошелька: `https://jobicy.com/api/v2/remote-jobs`. До 200 записей/страница, последовательный `nextCursor`; только публикации за 7 дней с задержкой 3 ч. Новый автоматический проход — не чаще раза/час; локальный кэш и guard общий для UI/API/MCP. Общую ленту загружай один раз на проход, затем фильтруй роли/компании локально, а не отдельным запросом на каждую компанию. Локальные maxPages/maxRequests ограничивают покрытие: не называй выдачу полной при достижении бюджета.

Сохраняй source=jobicy, ID, оригинальный Jobicy URL и видимую атрибуцию, описание, jobGeo/jobLevel и известную зарплату. Не выводи worldwide из одного remote; не приписывай неизвестный грейд. Бесплатный URL ведёт на Jobicy; прямые ATS URLs — отдельная платная функция, здесь не включена. Из исчезновения из семидневного окна не вычисляй закрытие: локального Jobicy status-refresh пока нет; проверяй первоисточник, а недоступность оставляй unknown/stale. [Официальные условия](https://jobicy.com/jobs-rss-feed).

## LinkedIn identity — один раз, refresh — отдельно

Ищи `site:linkedin.com/company/ "ИМЯ ИЗ БАЗЫ"` и при необходимости домен. Основание: ссылка с официального сайта, соответствие домена, деятельности, региона и известных алиасов. Одного совпадения названия недостаточно; ссылки на официальный домен в чужом профиле тоже могут быть ложными. Подтверждай совокупность признаков, неоднозначное сохраняй `needs_review`. Не меняй Company.name и внутренний companyId именем/ID LinkedIn.

Сохраняй canonical `https://www.linkedin.com/company/{slug}/`, evidence URLs/обоснование, дату проверки и метод. Числовой `externalCompanyId` сохраняй только из достоверной ссылки See all jobs/предоставленного Jobs URL с единственным числовым `f_C`; не выдумывай ID из slug. Без числа допустим `identityStatus=slug_only` при подтверждённой связи компании со страницей. В UI — `/company/{slug}/jobs/`, при достоверном числе — `/jobs/search/?f_C=...`. Это пользовательские ссылки, не программный API и не гарантия доступности без входа.

При мониторинге повторно используй эту identity. Адресный web search: `site:linkedin.com/jobs/view/ "ИМЯ" ("Product Analyst" OR "Data Analyst")`; роли, исключения и географию бери из текущего профиля. Разбивай длинные запросы на небольшие группы. `f_C` не фильтрует выдачу Google надёжно. Результат должен содержать именно работодателя, а не упоминание клиента в описании.

Агент применяет собственный доступный web search и передаёт проверенные результаты существующим import/research tools. Локальный Node-сервер не получает возможности Codex web search автоматически. Не изображай несуществующий executor/LinkedIn API. SerpAPI `google_jobs` не является organic web search; любой будущий organic executor обязан использовать общую квоту SerpAPI, общий metered transport и отдельную авторизацию пользователя. В текущем задании такой executor не добавляется.

## Границы обхода и импорт вакансий

- Только адресный поисковый поиск публично индексируемых страниц и официальные публичные Careers/ATS. Не использовать личный LinkedIn-аккаунт, cookies, автоматический Playwright-обход LinkedIn, `jobs-guest` endpoints, CAPTCHA bypass, proxy rotation или обход login wall. При ограничении остановить чтение страницы и сохранить пробел; доступность страницы не разрешает массовое копирование.
- Выделять числовой LinkedIn Job ID из `/jobs/view/{id}/` и варианта с текстовым slug; нормализовать URL и удалять tracking. Ни текстовый slug, ни число подписчиков не доказывают работодателя. Сначала проверить работодателя и первоисточник. Короткий snippet — кандидат; недостаточный материал не объявлять проверенной активной вакансией.
- Дедупликация: LinkedIn Job ID/canonical URL → подтверждённый ATS ID/URL → существующее сопоставление компании, роли и географии. При подтверждённой эквивалентности сохранять одну ATS-карточку и оба происхождения. Не сбрасывать stage/favorite/notes/followUp/AI/history.
- Разделять publishedAt, индексирование, discoveredAt/observedAt и проверку активности. Неизвестную дату оставлять неизвестной. Исчезновение из Google не закрывает роль; не передавать поисковую выдачу как полный ATS snapshot для missing_count.
- Поисковые планы/кандидаты сами не пополняют счётчики. Сохранение проверенных вакансий — прежний ATS import; research import хранит ссылки/evidence, не создаёт вакансии автоматически.

## Хранение и отображение

`Company.hiringSources` — опциональный JSON в прежней таблице companies: Careers, ATS-кандидаты/подтверждения, LinkedIn identity, проверенные URL/обоснования/даты и notes о пробелах. Старые базы совместимы; export/import и HTTP company PATCH используют прежний company-контракт. Не создавать параллельную систему вакансий. Новый SQL-файл или отдельная база не нужны.

### Полезные ссылки компании

При discovery/enrichment и чтении новых материалов в monitoring сохраняй конкретные связанные с компанией страницы источников, включая её профиль Indeed/Adzuna/WTTJ/Wellfound, если он действительно найден и использован. Поисковый запрос или наличие общего API не доказывает существование профиля работодателя: не генерируй URL и не называй общую выдачу профилем. Прежние Careers/ATS/LinkedIn identity продолжай хранить в `hiringSources`, прочитанные материалы — в evidence/collection_sources.

Для каталога «Полезные ссылки» используй дополнительный `Company.sourceLinks` через прежний `PATCH /api/companies/:id`: массив `{label,url,kind,parentUrl?,note?}`, где kind = blog/article/careers/ats/linkedin/profile/other. Названия короткие: «Технический блог», «Доска Greenhouse», «Профиль Indeed». Перед обновлением прочитай и дополни существующий массив; не заменяй каталог одной новой ссылкой. У блога сохраняй проверенную главную страницу (`kind=blog`), у использованных статей — их исходные URL (`kind=article`, `parentUrl` = главная блога). Главная блога не заменяет article evidence и сама по себе не подтверждает тег. Непроверенный домашний адрес не угадывай; сохрани статью и пробел. Нерелевантные новые статьи не добавляй только ради наполнения каталога. При мониторинге отдельный массовый ресерч ссылок не требуется.

Модалка в конце колонки «Компания» объединяет этот каталог с сохранёнными Careers/ATS/LinkedIn, evidence всех критериев и рисков, collection_sources и историческими вакансиями; одинаковые URL объединяются, статьи показаны под сохранённым блогом. «Вся информация» группирует факты по типу и перечисляет источники в соседней колонке: не дублируй один ответ для каждого источника, сохраняй различия по роли/стране/дате и существенные оговорки. История observations/review остаётся в базе. Операции импорта, добавления и обновления данных доступны модели через API/MCP; кнопок этих операций на вкладке сравнения нет.

В «Целевых вакансиях» после сводки/городов и после списка в модалке — лаконичные Careers и LinkedIn Jobs, только для подтверждённых identity. Общий справочник API остаётся по клику на заголовок. Проверка ссылки/identity не обновляет активность вакансий или дату ATS sync. В исследовании сохраняй collection_sources для каждого реально использованного web search/официального сайта, отдельно от метаданных URL. Автоматическое расписание не включается.
