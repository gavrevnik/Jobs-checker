# Зарплатные ориентиры Levels.fyi через бесплатные страницы

Применять при discovery новой компании и полном enrichment существующей. Обычный мониторинг вакансий не обязан повторять salary research. Это адресный веб-ресерч, без API/MCP Levels.fyi, платных Actors и подписок. Сначала переиспользовать свежие сохранённые данные; отсутствие публичной выборки не является отрицательной оценкой компании.

## Поиск и границы

- Найти страницу существующего работодателя на levels.fyi, проверить название/домен/identity. Открыть конкретную роль и страну; приоритет Product Analyst / Data Analyst, нужный Senior/уровень и страна профиля. При отсутствии точной роли допустима отдельно помеченная смежная DS/BI/Business Analyst; не подставлять её как зарплату Product Analyst.
- Читать публичный HTML. Если сайт сам предоставляет `.md` для этой salary-страницы, можно прочитать и его как веб-документ по llms.txt/robots.txt. Это не требует подключения платного API. Если Markdown не читается, использовать доступную HTML-страницу, а не скрытые JSON/GraphQL endpoints, выгрузки или reverse engineering.
- Только содержательная прочитанная страница подтверждает данные. Поисковый snippet — кандидат. При login/paywall/CAPTCHA/блокировке остановиться, сохранить partial/blocked в истории; не обходить ограничение и не заполнять salary по карточке другого работодателя/страны.
- Держать поиск адресным: одна нужная роль/страна, затем близкая роль при полезности. Не обходить весь каталог и все локализации. Не копировать индивидуальные зарплатные строки массово. Для результата обязательна атрибуция Levels.fyi и прямая ссылка на использованную страницу.

## Что сохранять

Новый descriptive **A07_SALARY_BENCHMARK** — отдельный рыночный ориентир. Удалённый A06 не возвращается; зарплата вакансии остаётся в ATS. Ориентир не добавляет score и не меняет зарплатные фильтры вакансий.

- В **scope** обязательно точное название роли (`role`) и ISO-2 `country`; `level`/`city`, только когда прямо определены. Глобальную сумму компании не приписывать стране профиля. Зарплата Data Analyst всех уровней не становится зарплатой Senior.
- В **value** обязательно компонент `total|base|stock|bonus|sign_on`, статистика `median|mean|range|individual`, сумма `amount` либо `min/max`, валюта ISO-3, период `year|month|hour`. Один observation — один компонент и согласованный набор фильтров. Не смешивать медиану общего заголовка, среднее по грейду и пример отдельного пакета; не складывать несовместимые компоненты. Ноль только при явном нуле, не при отсутствии поля. Показанную валюту не угадывать по стране; валюту заголовка и таблицы проверять отдельно, FX самостоятельно не применять.
- **sample_size** — опубликованный размер выборки или `null`; **sample_scope** = `role_country_level|role_country|company_role|individual|not_disclosed`. Если написано только «N salary submissions at Company», сохранять `company_role`, не выдавать это N за выборку нужной страны/грейда. Не считать видимые строки/placeholder-строки размером выборки; один Median Package card не означает N=1. Если N не раскрыт: null + not_disclosed.
- **source_updated_at** — прямо указанная дата обновления страницы либо null. **sample_period** — опубликованное окно данных либо null; «Last updated» не означает «данные за последние 12 месяцев». Фактическое время чтения — `evidence.observed_at`, отдельно от даты данных. Не заполнять published_at датой обновления и не объявлять старую статистику новой после повторного просмотра.
- **role_relation** = `target|related`; **notes** объясняет применимость/ограничения: смешанные уровни, нераскрытый охват N, округление, неизвестное окно данных. Малое N отметить как слабый ориентир, не как гарантированную вилку.
- **evidence.source_type=market_estimate**, URL, title и короткая дословная выдержка с числом и контекстом. Пользовательские сообщения остаются рыночной оценкой даже после проверки ссылки. Отдельная новая observation при обновлении, без уничтожения истории; разные даты/роли/страны не объединять в одну сумму.

Пример value для **вымышленной** страницы Data Analyst, ES (не реальные данные компании):

```json
{
  "component": "total",
  "statistic": "median",
  "amount": 50000,
  "min": null,
  "max": null,
  "currency": "EUR",
  "period": "year",
  "sample_size": 20,
  "sample_scope": "company_role",
  "source_updated_at": "2026-10-01",
  "sample_period": null,
  "role_relation": "target",
  "notes": "N относится к компании и роли; охват страны и грейда не уточнён."
}
```

## Неоднозначности и сохранение

Если заголовок/FAQ, страны или валюты противоречат друг другу и однозначно согласовать цифры нельзя, не выбирать удобную цифру. Сохранить страницу/описание расхождения в collection_sources/notes с outcome=partial, без численного benchmark; это не подтверждённый диапазон. Можно использовать другой согласованный срез той же страницы (например, отдельный явно подписанный грейд), только с собственными scope/статистикой и опубликованным N либо null.

Подготовить прежний preview → matching → разрешённый import → содержательный review. При текущей просьбе исследовать и сохранить рутинное локальное сохранение разрешено по workflow-common; чужой внешний JSON сохраняет свой прежний approval-порядок. source_updated_at и observed_at остаются отдельными датами. В «Вся информация» показываются роль/страна/грейд, сумма/компонент/статистика, N и область выборки, дата данных, источник и оговорка рыночной оценки. Не создавать отдельную колонку зарплат и не подставлять benchmark в карточку вакансии.

В историю исследования записать фактически открытые URL, время чтения, successful/partial/blocked/empty и найденные пробелы. «Публичная страница не перечисляет роль» не равняется «у компании нет аналитиков». Проверка ссылок и сохранение не запускают API/Actors и не ставят расписание.
