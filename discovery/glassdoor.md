# Glassdoor по явному запросу

Оба адаптера подключены через [общий клиент Personal Radar](../../personal-radar/docs/glassdoor.md). Обычный поиск, обогащение, мониторинг, просмотр карточки, тесты и запуск приложения не вызывают Actor. Платные операции проходят через `ResearchPaidGate`.

- Основной адаптер для интервью по роли (`P07_INTERVIEW`) — `scrapifier/glassdoor-interviews-scraper`. Если публичный поиск показал только часть отчёта, передай проверенный `companyUrl` и точный `jobTitle` из отчёта. `volume` ограничивает число записей. Фильтр Glassdoor может включать близкие роли, поэтому сверяй должность и ID отчёта. [Описание Scrapifier](https://apify.com/scrapifier/glassdoor-interviews-scraper)
- `memo23/glassdoor-scraper-ppr` выдаёт отзывы (`P01`) и интервью (`P07_INTERVIEW`) по компании. Подключённая операция принимает необязательную дату начала и работает без фильтра интервью по должности. Используй по отдельному запросу на выборку по компании. [Описание memo23](https://apify.com/memo23/glassdoor-scraper-ppr)

## Публичный поиск и запись в карточку

1. Найди профиль работодателя на Glassdoor и сверь его с карточкой компании. Пройди доступные разделы Interviews и Reviews. Ищи также отдельные страницы отчётов и вопросов через `site:glassdoor.com/Interview` с названием компании, целевой ролью и её вариантами. Для аналитика проверь, например, `Product Analyst`, `Data Analyst`, названия из вакансии и смежные роли с похожими задачами. Дополняй поиск по компании и роли словами `take-home`, `case study`, `SQL`, `A/B test` и аналогами по контексту. Просматривай доступную выдачу и переходи к материалам, пока находятся новые релевантные записи. Укажи, какие страницы и фильтры были доступны, а какие потребовали вход или не открылись.
2. Отбирай отчёты об интервью и отзывы по роли, команде или офису, из которых следует конкретика для подготовки. Сохраняй роли, локации и даты публикации и интервью по отдельности, когда они известны. Для интервью укажи этапы, инструменты и вид задания. Зафиксируй вводные, что требовалось сделать и сдать, время и обратную связь, если источник даёт эти детали. В `questions` помечай формулировку источника `quoted`, пересказ — `paraphrased`. Если автор описал только формат задания, сохраняй именно его. Отмечай наблюдения об опыте кандидата как рассказ с указанного интервью.
3. Передай отобранные записи в `jobs_company_glassdoor_save({companyId,entries})` или `POST /api/company-research/:companyId/glassdoor-info` с `{entries}`. Поле `glassdoor_info` видно в разделе «Glassdoor» карточки компании. Каждая запись содержит `kind` (`interview` или `employee_review`), `id` и `sources` с методом, ссылкой и датой проверки `checkedOn`. Используй `public_web` для публичного веб-поиска, `browser` для просмотра в браузере и `apify` с `runId` для датасета. Привязывай ссылку к конкретному отчёту или вопросу, когда ссылка доступна. `summary` содержит краткий разбор, `assignments` — формат (`take_home`, `live`, `unspecified`), `details` и, если указан, `timeLimit`. Для неизвестных значений пропусти поле.
4. Используй `report:<RVW ID>` для отчёта, включая `recordId` из Apify, и `question:<QTN ID>` для отдельного вопроса без связанного отчёта. Если вопрос удалось связать с отчётом, добавь его в `questions` этой записи. При совпадении ID источники и детали объединяются. Для уже собранного датасета используй `jobs_company_paid_collect` и сохраняй только отобранные материалы. Публичный поиск входит в `jobs-deep-discovery`, платный сбор запускается по правилам ниже.

## Настройка

В ignored `.env` Jobs Checker самостоятельно задать `APIFY_TOKEN` своего Apify account. Не переносить ключ соседнего проекта автоматически. `JOBS_GLASSDOOR_MAX_RUN_USD=1` — локальный потолок на один запуск, допустимо >0 и <=10. Это не месячный бюджет и не отдельный allowance Jobs: при одном аккаунте расходы делятся с Personal Radar/Activity Checker. После настройки перезапустить Jobs и MCP обычным lifecycle. Наличие ключа — configured, не проверка его валидности/баланса.

## Порядок запуска

1. `jobs_company_paid_status` — локальные capability, missing credentials и лимиты, без HTTP провайдера.
2. Установить точное соответствие companyId и профиля Glassdoor по названию, домену и деятельности. Бесплатные источники остаются первым шагом. Подготовить конкретные URL, reviews/interviews, объём и период.
3. Для запроса на сбор и разбор добавь `readResults: true` в `operation`. `jobs_company_paid_quote({operation})` читает актуальный тариф Actor. При оценке расходов учитывай отдельно чтение и передачу данных по [тарифу платформы Apify](https://docs.apify.com/actors/running/actors-in-store). Если конкретный запуск ещё не согласован, покажи его параметры и смету.
4. Только после явного пользовательского запроса с этими параметрами: `jobs_company_paid_authorize({operation,confirmed:true})`. Повторное разрешение не спрашивать, если оно уже дано на тот же конкретный запуск. Возвращает grantId на один час, привязанный к неизменной operation. Это ещё не исполнение.
5. `jobs_company_paid_execute({operation,grantId})` запускает Actor одним POST с `maxTotalChargeUsd` и сохраняет его в журнале. С `readResults: true` он ждёт завершения через один запрос метаданных с ожиданием до 20 секунд, если запуск ещё активен, затем читает успешный результат. Без флага возвращаются метаданные запуска и ссылки. При неизвестном исходе POST проверь журнал и Console перед любыми дальнейшими действиями.
6. `jobs_company_paid_runs({ledgerId?})` читает SQLite; без ID возвращает последние 20 запусков. `jobs_company_paid_refresh({ledgerId})` делает один явный GET metadata **уже сохранённого run ID**, обновляет status/cost в ledger, не запускает Actor и не читает dataset. Если POST не вернул ID, проверять Console вручную, а не угадывать run по истории аккаунта.
7. `jobs_company_paid_collect({ledgerId})` читает сохранённый запуск по запросу пользователя и продолжает сбор после `collection.status=pending`. Берёт dataset ID из журнала и читает только поля нормализатора, одним запросом и в пределах исходного объёма. Повторное чтение после успеха использует локальный кэш. Для скачанного вручную JSON доступен `jobs_company_paid_normalize({ledgerId,rows})`. Оба пути возвращают материалы P01/P07_INTERVIEW, причины отклонения строк и происхождение данных. Сохранение наблюдений проходит через обычное ревью.

Пример **шаблона**, не согласие и не команда к исполнению:

```json
{
  "provider": "apify",
  "actor": "scrapifier/glassdoor-interviews-scraper",
  "operation": "interviews",
  "companyIds": ["EXISTING_COMPANY_ID"],
  "volume": 10,
  "parameters": {
    "companyUrl": "https://www.glassdoor.com/Interview/Example-Interview-Questions-E123.htm",
    "jobTitle": "Product Analyst"
  },
  "maxCostUsd": 0.03,
  "readResults": true
}
```

URL и ID в примере вымышлены. Перед запуском получи актуальный тариф и согласуй бюджет. Один запуск охватывает одну компанию и один тип данных, максимум 200 строк. `maxCostUsd` ограничивает запуск Actor. Чтение датасета и передача данных после завершения учитываются в Apify отдельно, в том числе при ручном экспорте.

## HTTP

Все маршруты под `/api/company-research/paid`; сохраняют прежние loopback/Host/Origin проверки.

| Метод/маршрут | Body | Эффект |
| --- | --- | --- |
| GET `/` | — | Локальный status |
| POST `/quote` | `{operation}` | Один GET актуального публичного тарифа |
| POST `/authorize` | `{operation,confirmed:true}` | GET тарифа + локальный одноразовый grant |
| POST `/execute` | `{operation,grantId}` | Резерв бюджета, GET тарифа, единственный POST запуска, чтение результата с `operation.readResults: true` |
| GET `/runs` или `/runs/:ledgerId` | — | Локальная история/результат |
| POST `/runs/:ledgerId/refresh` | `{}` | GET метаданных run + обновление ledger |
| POST `/runs/:ledgerId/collect` | `{}` | Чтение результата сохранённого запуска Apify или локального кэша |
| POST `/runs/:ledgerId/normalize` | `{rows:[...]}` | Offline нормализация; ничего не импортирует |

`status=submitted` в журнале означает отправленную операцию. Фактический статус Apify находится в `result.data.status`, результат сбора — в `collection`. Если чтение не удалось, сохранившийся `ledgerId` позволяет обратиться к результату ещё раз без запуска Actor. `costUsd` содержит стоимость запуска, `null` означает неизвестную сумму. `costProvisional=true` означает предварительные данные Apify. Для нового запуска требуется новый grant. Нормализованные материалы хранятся в существующем журнале SQLite и выдаются при чтении датасета.

Свежесть, конкретная роль и страна, повторяемость и содержательность отзывов важнее общего рейтинга. Различай официальное описание найма и рассказы кандидатов. `durationDays` — длительность всего процесса. Для `identityBasis=input_url_only` дополнительно проверь работодателя. Происхождение `apify_dataset_api` подтверждает, откуда получены данные, а содержание отзывов требует отдельной проверки.
